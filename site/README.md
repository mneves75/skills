# site/ (GitHub Pages)

Published at https://mneves75.github.io/skills/ by `.github/workflows/static.yml` after CI
succeeds on the current `main` commit. Manual rollback uses
`gh workflow run static.yml -f ref=<earlier tag or commit>`; the selected commit must be on
`main` and its latest CI push run on `main` must have succeeded. Missing, failed or unfinished
CI evidence stops publication. `python3 tools/scripts/check-pages.test.py` exercises this
guard with real Git commits and a fake CI provider; it does not publish the site.

Before merging, follow [Preparing a Release](../CONTRIBUTING.md#preparing-a-release).
Successful CI does not replace security/readiness verdicts or owner waivers. After Pages
finishes, compare the served files with the approved commit's `site/` bytes; a completed
workflow alone is not live-content proof.

- `index.html`: landing page. Hand-written, self-contained; edit directly.
- `howto.html`: rendered from [HOWTO.md](../HOWTO.md) by `tools/scripts/build-site.sh`. Do not edit by hand.
- The changelog rows in `index.html` (between the `changelog:start/end` markers) are generated by the same script from `CHANGELOG.md`.
- The catalog currently includes seventeen skills and links the separate 36-skill pstack collection. The "Plan & deliver" group title links the SRE guides (`docs/sre-guides/`) and prompts (`docs/sre-prompts.md`), outside the skill cards, because `build-site.test` treats every link inside a card as its guide link; they are documents, not skills. The independent browser check on 2026-10-23 covered this seventeen-card Council/security-audit catalog at 1440x900 and 390x844: both new cards render with their guide links and release notes, guide anchors `#council` and `#security-audit` exist in the generated page, the copy control passes its three scenarios, the hero count reads seventeen, and no horizontal overflow appears at 390px.
- The generated guide uses a main landmark and keyboard-focusable code/table scroll containers with visible focus indicators.
- `bash tools/scripts/build-site.test` checks the real generator for complete output, catalog/guide consistency, semantic keyboard access and repeatable rebuilds in an isolated copy.
  When adding a skill, update its landing card and the HOWTO source, then run
  `tools/scripts/build-site.sh` to keep the generated usage page and changelog current.
- `fastapi.html`: sample report from the readiness-check tool (FastAPI `9a8a13f`, 2026-08-26, `--skip-tests --skip-build`).

Regenerate the sample report from a FastAPI checkout:

```bash
bun --bun /path/to/skills/tools/readiness-check.ts --format=html --skip-tests --skip-build --output=/path/to/skills/site/fastapi.html
```
