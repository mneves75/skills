# pstack collection

32 skills from [pstack](https://github.com/cursor/plugins/tree/main/pstack), Lauren Tan's
engineering skill stack, in the [Agent Skills](https://agentskills.io/specification) format.
Every agent that reads that format can load them; how much of each workflow runs depends on
the agent (see [Support by agent](#support-by-agent)).

The skills come from [`michael-denyer/pstack-claude`](https://github.com/michael-denyer/pstack-claude),
which ports pstack to Claude Code, Codex and Pi, plus three local commits described under
[Deviations](#deviations). [`UPSTREAM`](UPSTREAM) names the published commit they sit on
(`based-on`), and [`local-overrides.patch`](local-overrides.patch) holds the local commits'
changes to the skills. `skills/`, `UPSTREAM`, `LICENSE` and the patch are generated by
[`tools/scripts/sync-pstack.sh`](../../tools/scripts/sync-pstack.sh); do not edit them by hand.

## Install

This collection sits outside `skills/`, so a plain `npx skills add mneves75/skills` does not
install it. Choose one:

```bash
# All 32 pstack skills, interactive agent choice
npx skills@latest add https://github.com/mneves75/skills/tree/main/collections/pstack/skills

# One skill
npx skills@latest add mneves75/skills --full-depth --skill poteto-mode

# Manual: clone once, then link the skills into the agent's skills directory
git clone https://github.com/mneves75/skills.git
ln -s "$PWD/skills/collections/pstack/skills/"* ~/.agents/skills/   # Codex, shared catalog
```

The manual install table in the [root README](../../README.md#manual-git-clone) lists the
skills directory for each agent.

## Support by agent

These are the skills alone. The pstack-claude plugin also ships plugin agents
(`pstack:poteto-agent`, `pstack:comment-sicko` and the effort agents), a routing hook, and a Pi
extension with the subagent and question tools. This collection ships none of them.

| Agent | What works from this collection |
|---|---|
| Claude Code | Every skill. Skills that dispatch a `pstack:*` agent need a general-purpose subagent instead; for `no-comments`, pass `poteto-mode/references/agents/comment-sicko.md` as its instructions. |
| Codex | Every skill. `poteto-mode/references/codex-tools.md` maps the Claude Code tool names to Codex's. Same `pstack:*` caveat. |
| Pi | Every skill, but the fan-out skills (`interrogate`, `why`, `how`, `arena`, `reflect`) run one sequential pass: their subagent and question tools come from the Pi extension, which is not here. |
| Cursor, Gemini CLI, OpenCode, Copilot and other readers | The single-agent skills (`bro`, `tdd`, `technical-writing`, `typescript-best-practices`, `correct`, the PR skills and similar). Skills that spawn subagents or ask structured questions name Claude Code tools; the agent must map them to its own or run them sequentially. |

`poteto-mode` loads only when you ask for it: the routing hook that injects it is part of the
plugin. For the full workflows on Claude Code, Codex or Pi, install pstack-claude as its README
describes. Do not install both under the same agent: the skill names collide.

## Adaptation applied by the sync

Frontmatter keys outside the Agent Skills spec move under `metadata:`, so strict loaders and
`skills-ref validate` accept every skill. Two skills are affected: `poteto-mode`
(`menu-description`) and `typescript-best-practices` (`paths`). Claude Code no longer limits
`typescript-best-practices` to `.ts`/`.tsx` paths; its description still names those files.
Bodies are byte-identical to the source commit.

## Deviations

**From upstream pstack**, as pstack-claude ships it: eight skills are pstack-claude additions
(`babysit` and `deslop` as Claude Code analogs of Cursor built-ins, `thermo-nuclear-code-quality-review`,
and five PR skills imported from Cursor's team kit: `fix-ci`, `fix-merge-conflicts`,
`get-pr-comments`, `make-pr-easy-to-review`, `what-did-i-get-done`). pstack-claude does not port
`make-bot-ui`, which targets Grok Bot webhooks.

**From pstack-claude**, the three local commits in `local-overrides.patch` change four things:

1. **Models.** Claude-side roles use Opus and Fable only. Panels that upstream fills with a
   third Claude model run with two, so on Claude Code `interrogate`, `arena` and `architect`
   panels are same-family. The GPT side is unchanged.
2. **Autonomy.** `poteto-mode` works without asking only on the local machine. It stops before
   push, deploy, publish, sending messages, any other external write, credentials, or scope
   expansion. Reach, not reversibility, decides.
3. **Consolidation.** The 24 `principle-*` skills and the always-on `unslop` skill are retired.
   Their guidance lives in four `poteto-mode/references/engineering-*.md` documents that the
   other skills link to.
4. **Names.** `tdd` and `teach` keep their pstack names, although Matt Pocock's skills use the
   same names. See below.

## Conflicts with Matt Pocock's skills

Checked on 2026-10-04 against [`mattpocock/skills`](https://github.com/mattpocock/skills) at
`24fe0ef` (37 skills), plus `resolving-merge-conflicts`, which he has since removed but which
older installs still carry.

**Name collisions: install one or the other.** An agent loads one skill per name, and the
`skills` CLI overwrites the earlier install.

| Name | pstack | Matt Pocock |
|---|---|---|
| `tdd` | "Use only when the user explicitly asks for TDD, a failing test, or a regression test", or when the bug has an obvious cheap test target; skip it otherwise | "Use when the user wants to build features or fix bugs test-first", red-green-refactor |
| `teach` | Explains a body of work by running `how` and `why` | Teaches the user a new skill or concept inside the workspace |

The two `tdd` skills have opposite defaults. Installing pstack's in place of Matt Pocock's
removes the skill that writes tests first by default: if your own rules say tests come first,
state that rule in your agent instructions, because pstack's `tdd` will not apply it unasked.

**Purpose overlaps.** Two skills cover the same job. Where both are model-invocable, the agent
may pick either for the same request; skills marked † set `disable-model-invocation: true`, so
they run only when called by name and the overlap is a choice of which to call. Make the
descriptions disjoint, or uninstall one side, where the overlap matters to you.

| pstack | Matt Pocock | Overlap |
|---|---|---|
| `bro` | `wait-what`† | Both restate the last message in plain words. Near-duplicates. |
| `fix-merge-conflicts` | `resolving-merge-conflicts` | Same job. Matt Pocock removed his upstream. |
| `make-pr-easy-to-review`, `technical-writing` | `pr` | Writing the PR description. |
| `interrogate`, `thermo-nuclear-code-quality-review`, `make-pr-easy-to-review` | `code-review` | Reviewing a change. `interrogate` uses several models; `code-review` splits standards from spec. |
| `interrogate` | `grilling`, `grill-me`† | "Stress test". `interrogate` attacks an artifact; `grilling` interviews the user. |
| `why` | `diagnosing-bugs` | Regressions. `why` explains a cause from history; `diagnosing-bugs` runs a fix loop. |
| `reflect`, `correct` | `retro`† | Lessons from a session. `correct` also encodes each lesson as a check. |
| `recall` | `handoff`†, `claude-handoff`† | Session context. `recall` rebuilds your own; the handoffs write it for another agent. |
| `architect`, `figure-it-out` | `to-spec`†, `wayfinder`†, `codebase-design`, `improve-codebase-architecture`†, `prototype` | Planning and design before code. |
| `poteto-mode`, `swarm`, `arena` | `implement`†, `implement-spec`† | Carrying out a planned change. |
| `technical-writing` | `writing-shape`†, `writing-beats`†, `writing-for-agents` | Writing standards. |
| `setup-pstack` | `setup-matt-pocock-skills`† | Per-repo setup; pstack configures models, Matt Pocock configures the tracker. Different jobs, similar trigger. |
| `poteto-mode` | `ask-matt`† | Each routes to its own family of skills. |

No other names collide.

## Re-sync

From a pstack-claude checkout that is fetched and rebased onto its upstream:

```bash
git -C <path-to-pstack-claude> fetch origin
tools/scripts/sync-pstack.sh <path-to-pstack-claude> <commit>
bash tools/scripts/sync-pstack.test
```

To rebuild without the local fork, check out the public `based-on` commit from `UPSTREAM`,
`git apply` the patch, commit, and run the sync on that checkout.

Review the diff, update the counts in this README if skills were added or removed, and add a
`CHANGELOG.md` entry.
