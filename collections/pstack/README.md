# pstack collection

42 skills from [pstack](https://github.com/cursor/plugins/tree/main/pstack), Lauren Tan's
engineering skill stack, in the [Agent Skills](https://agentskills.io/specification) format.
Every agent that reads that format can load them; how much of each workflow runs depends on
the agent (see [Support by agent](#support-by-agent)).

## Where the skills come from

[`sources.json`](sources.json) pins two published repositories by full commit:

| Source | Commit | Version |
|---|---|---|
| [`michael-denyer/pstack-claude`](https://github.com/michael-denyer/pstack-claude), the Claude Code port the skills are taken from | `79b36d9b53a53c78e5ec26bf6ce7dade76686c87` | 0.9.128 |
| [`cursor/plugins`](https://github.com/cursor/plugins), the official upstream | `fd268b808c786469e6dd8c8d9db864d0de4d669e` | pstack 0.15.36 |

The sync refuses a port whose upstream pins have fallen behind the official commit:
[`UPSTREAM`](UPSTREAM) records each port component (`pstack` at `c742dd6`, `cursor-team-kit`,
`thermos`) as identical, on the paths the port takes, to that official commit. On top of the
port, the sync applies the seven patches in [`adaptations/`](adaptations/), in name order; each
patch opens with what it changes and where it came from. `UPSTREAM` records each patch's
SHA-256.

`skills/`, `UPSTREAM`, `LICENSE*` and `NOTICE-skills.md` are generated by
[`tools/scripts/sync-pstack.sh`](../../tools/scripts/sync-pstack.sh); never edit them by hand.
`README.md`, `sources.json` and `adaptations/` are written by hand.

## Install

This collection sits outside `skills/`, so a plain `npx skills add mneves75/skills` does not
install it. Choose one:

```bash
# All 42 pstack skills, interactive agent choice
npx skills@latest add https://github.com/mneves75/skills/tree/main/collections/pstack/skills

# One skill
npx skills@latest add mneves75/skills --full-depth --skill poteto-mode

# Manual: clone once, then link the skills into the agent's skills directory
git clone https://github.com/mneves75/skills.git
ln -s "$PWD/skills/collections/pstack/skills/"* ~/.agents/skills/   # Codex, shared catalog
```

The manual install table in the [root README](../../README.md#manual-git-clone) lists the
skills directory for each agent.

## Support by agent

These are the skills alone. The pstack-claude plugin also ships plugin agents
(`pstack:poteto-agent`, `pstack:comment-sicko` and others), hooks and per-agent extensions.
This collection ships none of them.

| Agent | What works from this collection |
|---|---|
| Claude Code | Every skill. Skills that dispatch a `pstack:*` agent need a general-purpose subagent instead; for `no-comments`, pass `poteto-mode/references/agents/comment-sicko.md` as its instructions. |
| Codex, GitHub Copilot, Muse | About twenty skills that call agent tools open with a pointer to that agent's mapping (`poteto-mode/references/codex-tools.md`, `copilot-tools.md`, `muse-tools.md`), which maps the Claude Code tool names. Same `pstack:*` caveat. Where the agent has no subagent or question tool, the fan-out skills (`interrogate`, `why`, `how`, `arena`, `reflect`) run one sequential pass. |
| Pi, MiniMax | `poteto-mode` and `setup-pstack` carry their mappings (`pi-tools.md`, `minimax-tools.md`); other skills map tools as for the readers below. |
| Cursor, Gemini CLI, OpenCode and other readers | The single-agent skills (`bro`, `tdd`, `technical-writing`, `typescript-best-practices`, `correct`, the PR skills and similar). Skills that spawn subagents or ask structured questions name Claude Code tools; the agent must map them to its own or run them sequentially. |

`poteto-mode` loads only when you ask for it: the routing hook that injects it is part of the
plugin. Do not install both this collection and pstack-claude under the same agent: the skill
names collide.

## Opt-in skills and their tools

Six skills are new in this sync: `statechart`, `create-formal-verification-skill`,
`maintain-formal-verification-skill`, `ketchup-video`, `in-your-own-words` and `sharpen`. The
first four, and the `thermos` reviews, say in their description that they run only when
invoked by name. That is an instruction to the agent, not an enforced setting: the Agent
Skills format has no field that stops model invocation on every host.

None of them installs anything on its own. An install runs only where the user or the host's
policy already authorized it; otherwise the agent asks immediately before it.

| Skill | Needs | Without it |
|---|---|---|
| `statechart` | A TypeScript-capable runtime (Node 22.18+ but not 23.0 to 23.5, Bun 1.1.5+ or Deno 2+); Java 11+ and TLC through mise, or `TLA2TOOLS` and `JAVA`; Pele for SVG output, optional | The runner stops and names the `mise install` command; without Pele the chart is handed over as Mermaid text, marked as not rendered |
| `create-formal-verification-skill`, `maintain-formal-verification-skill` | Whatever verifier fits the project (a model checker, a proof assistant, an SMT-backed verifier) | The skill says no verifier runs and tests with generated inputs instead |
| `ketchup-video` | An installed tool that renders frames to video | A failed render: one line saying so, then the calls as text |

`statechart/scripts/test`, upstream's 3.7 MB compiler test corpus, is excluded; the runner
does not read it. Its `package.json` therefore carries no test command. The adapted runner is
tested here by [`tools/scripts/statechart-runner.test`](../../tools/scripts/statechart-runner.test),
which runs it with fake `mise` and `java`: missing tools stop it without an install, and
found tools are the ones it runs. No test here runs real TLC; upstream's own tests do not cover
the adaptation.

## Adaptations

1. **Models and autonomy** (`01`). The Claude-side and Codex-side model roles follow the
   routing in the patch. `poteto-mode` works without asking only on the local machine and stops
   before push, deploy, publish, sending messages, any other external write, credentials or
   scope expansion. [`adaptations/tooling/port-models-policy.patch`](adaptations/tooling/port-models-policy.patch)
   restamps the port's generated model sections; the sync does not apply it.
2. **Consolidation** (`02`). The 24 `principle-*` skills and the always-on `unslop` skill are
   retired. Their guidance lives in four `poteto-mode/references/engineering-*.md` documents
   that the other skills link to.
3. **Test-first `tdd`** (`03`). It writes the failing test first for every bug fix or feature,
   skips prototypes, spikes and pure config, and names the check it used when no cheap test
   exists.
4. **Read-only `why`, bounded `babysit`** (`04`). `why`'s investigators and synthesizer never
   edit, and a denied read is never retried with broader access. `babysit` defers to an
   installed `babysit-pr`, keeps one owner per PR, writes only to the PR's head branch, reads
   every page of review comments, and reports its round cap as blocked.
5. **Explicit opt-in** (`05`). The skills above run only by name; `recall` reads chat history
   only on request; `automate-me` asks before mining transcripts and opens a PR only after
   approval; `correct` adds rules only in a requested run; `reflect` files backlog only with
   authorization; `get-pr-comments` reads every page.
6. **Install consent and scratch placement** (`06`). `statechart` and `ketchup-video` work in an
   allowed scratch folder and use installed tools, under the install rule above. `babysit`'s
   round cap yields to a stricter limit in the user's or repository's instructions, and the
   `poteto-mode` Babysit playbook stops as blocked when the same failure survives two fixes or
   after three push waves. `ketchup-video` and `create-formal-verification-skill` carry a
   fallback for a missing `ketchup` or `statechart`.
7. **Opus at medium effort** (`07`). An `opus` role value without an `@` suffix runs at `medium`
   whenever it resolves to an Opus model, whatever the sheet's `default effort` line says; an
   explicit suffix still wins, and a runtime that maps `opus` to another vendor's model keeps the
   default effort.

Frontmatter keys outside the Agent Skills spec move under `metadata:` (`poteto-mode`'s
`menu-description`, `typescript-best-practices`' `paths`), so strict loaders accept every
skill. Claude Code no longer limits `typescript-best-practices` to `.ts`/`.tsx` paths; its
description still names those files.

## Conflicts with Matt Pocock's skills

Checked on 2026-10-04 against [`mattpocock/skills`](https://github.com/mattpocock/skills) at
`24fe0ef` (37 skills), plus `resolving-merge-conflicts`, which he has since removed but which
older installs still carry. The six skills added in this sync were not rechecked.

**Name collisions: install one or the other.** An agent loads one skill per name, and the
`skills` CLI overwrites the earlier install.

| Name | pstack | Matt Pocock |
|---|---|---|
| `tdd` | Failing test first for every bug fix or feature; skips prototypes, spikes and pure config, and names the fallback check when no cheap test exists | "Use when the user wants to build features or fix bugs test-first", red-green-refactor at agreed seams |
| `teach` | Explains a body of work by running `how` and `why` | Teaches the user a new skill or concept inside the workspace |

Both `tdd` skills write tests first. They differ in method: Matt Pocock's confirms the test
seams with you before writing a test, while this one picks the narrowest existing check and
quotes the failure before fixing. Matt Pocock's `implement` and `implement-spec` call `tdd` by
name and get whichever is installed.

**Purpose overlaps.** Two skills cover the same job. Where both are model-invocable, the agent
may pick either for the same request; skills marked † set `disable-model-invocation: true`, so
they run only when called by name and the overlap is a choice of which to call. Make the
descriptions disjoint, or uninstall one side, where the overlap matters to you.

| pstack | Matt Pocock | Overlap |
|---|---|---|
| `bro` | `wait-what`† | Both restate the last message in plain words. Near-duplicates. |
| `fix-merge-conflicts` | `resolving-merge-conflicts` | Same job. Matt Pocock removed his upstream. |
| `make-pr-easy-to-review`, `technical-writing` | `pr` | Writing the PR description. |
| `interrogate`, `thermo-nuclear-code-quality-review`, `make-pr-easy-to-review` | `code-review` | Reviewing a change. `interrogate` uses several models; `code-review` splits standards from spec. |
| `interrogate` | `grilling`, `grill-me`† | "Stress test". `interrogate` attacks an artifact; `grilling` interviews the user. |
| `why` | `diagnosing-bugs` | Regressions. `why` explains a cause from history; `diagnosing-bugs` runs a fix loop. |
| `reflect`, `correct` | `retro`† | Lessons from a session. `correct` also encodes each lesson as a check. |
| `recall` | `handoff`†, `claude-handoff`† | Session context. `recall` rebuilds your own; the handoffs write it for another agent. |
| `architect`, `figure-it-out` | `to-spec`†, `wayfinder`†, `codebase-design`, `improve-codebase-architecture`†, `prototype` | Planning and design before code. |
| `poteto-mode`, `swarm`, `arena` | `implement`†, `implement-spec`† | Carrying out a planned change. |

| `poteto-mode` | `ask-matt`† | Each routes to its own family of skills. |

No other names collide.

## Re-sync

The sync reads two local clones and fetches nothing: every Git call runs with
`GIT_NO_LAZY_FETCH=1`, so a commit or object the clone lacks fails the run. It needs the
Agent Skills reference validator (`agentskills`, from skills-ref) on PATH and validates every
generated skill with it before anything replaces the current collection.

```bash
git clone https://github.com/michael-denyer/pstack-claude <port>
git clone https://github.com/cursor/plugins <official>
tools/scripts/sync-pstack.sh <port> <official>
bash tools/scripts/sync-pstack.test
```

To move to newer sources, change the two commits in `sources.json`, refresh any patch in
`adaptations/` that no longer applies, and run the sync. A failed run leaves the collection
byte-identical. Review the diff, update the counts in this README if skills were added or
removed, and add a `CHANGELOG.md` entry.
