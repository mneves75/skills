# 2026-10-15

Evaluated the no-cost DeepSeek V4.1 Flash on OpenCode as a worker for plans written by other
models. Headless `opencode run` works (stdin prompts, JSON events, session continuation, model
identity in `session export`) and four benchmark tasks with hidden tests matched the Codex worker.
The harness is the risk: twenty-four hazards reproduced (and one hypothesis), recorded in
`docs/specs/opencode-worker/spec.md`.

Three adversarial reviews changed the design. The advisor found that project configuration
outranks the user profile (then reproduced: planted config and plugin both took effect). The
plan advisor found that Codex's sandbox leaves reads open (then reproduced: a `deny_read`
requirement in a private Codex home was ignored) and that the benchmark supports feasibility, not
a role binding. The lane therefore generates its own Seatbelt profile, gives the worker a private
home and stores, and ships as an opt-in trial that binds no model and changes no role.

Acceptance of the delegated build found its box profile written in a shape opencode silently
ignores: the fake-binary test asserted the file's contents, not the rule's effect. Only a live
behavioral probe (a denied command that ran) exposed it; a Code Mode bypass of the web deny and
open keychain and clipboard services surfaced the same way.

Incident: a probe meant for a throwaway repo ran `git reset --hard HEAD` in the main checkout,
because the harness took `$PWD` from the caller. The tree was clean before and after at the same
commit. Live model ids re-verified with a fake-id negative control (400).
