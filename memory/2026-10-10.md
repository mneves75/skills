# 2026-10-10 — 1.33.0: mneves-background-sessions

Added `mneves-background-sessions`, a coordinator procedure that runs one background Claude Code
session per unit of work. The idea comes from diegohaz's orchestrate-background-sessions gist
(revision `e88272cf`), which carries no license. So it is an original Apache-2.0 skill with the
`mneves-` prefix, not an adaptation: NOTICE, README and HOWTO credit the gist as inspiration
only. A first draft followed the gist's sentences too closely (213 shared eight-word runs); it
was rewritten until the only shared runs were the `claude --bg` flag syntax.

Corrected the gist against Claude Code 2.1.295 and its docs: session state comes from
`claude agents --json`, not internal job files; cost comes from transcript `usage` fields
without naming an internal path; background sessions isolate into a worktree even without
`-w`; cross-session messaging needs 2.1.224+ (2.1.234+ on native Windows), and a
`bypassPermissions` worker holds messages unless `crossSessionInbound` is `"accept"`. The
availability of `--permission-mode auto` on every plan and provider remains unverified and the
skill says so. Model choice is expressed as capability roles; tier words appear only in the
`--effort` flag line.

Fable Defaults rechecked against the OpenAI model docs and the Anthropic models overview and
Claude Code alias tables; every id is current, so only the verified-on date moved.

Local environment notes, not repository problems: the installed `bunx` shim failed with
`File not found "marked@18.0.13"` while `bun x` worked, so the site was built with a temporary
`bunx` -> `bun x` shim on `PATH`; the skills CLI needs Node 22 (`fs/promises` `glob`), so
`--list` ran through `npx -p node@22`. The change is Markdown only, so there was no supported
source for `cccc`.
